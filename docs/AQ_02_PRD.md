# AQ_02. Product Requirements Document (PRD)

Status: DRAFT v0.1 | Owner: Pramod Kumar

## 1. Goal
Publish a free, honest Delhi-NCR air quality forecast (D+1, D+2) as a web page and Android app, with measured accuracy shown next to simple baselines.

## 2. Users
| Persona | Need |
|---------|------|
| Parent / commuter | "Should kids play outside tomorrow? Mask for the commute?" |
| Outdoor exerciser | Pick a good day/time window |
| Person sensitive to air pollution (or family) | Early warning with a clear, cautious health note |

## 3. Non-goals
Medical advice, accounts, ads, in-app purchases, other cities, iOS, real-time sensor network, source attribution, claims of beating official forecasts.

## 4. Tiers and cut order
| Tier | Content | Cut order |
|------|---------|-----------|
| MUST | Data ingestion + archive; baselines; forecast job; static JSON; evaluation report; web page | never |
| MUST | Android app: area picker, today + D+1 + D+2, health note, disclaimer, data attribution | never |
| SHOULD | Probability of "Poor or worse"; "how we did yesterday"; local notification alert; Hindi | cut 3rd |
| COULD | Fire hotspot feature (FIRMS); station map; widget | cut 1st |
| COULD | Play Store production release | cut 2nd; web page + GitHub APK remain |

## 5. Functional requirements
| ID | Requirement | Tier | Acceptance |
|----|-------------|------|------------|
| FR-01 | Show current category and PM2.5 for chosen area with data time | MUST | Time shown, stale data flagged |
| FR-02 | Show D+1 and D+2 forecast: category, PM2.5 range (interval) | MUST | Matches published JSON |
| FR-03 | Show probability that category is Poor or worse | SHOULD | Calibration checked in eval |
| FR-04 | Show baseline next to model ("simple guess: ...") and last 7 days hit/miss | SHOULD | Numbers from archive |
| FR-05 | Short health note per category, with disclaimer | MUST | Reviewed text (AQ_16) |
| FR-06 | Area picker (no location permission) | MUST | Works offline with cached data |
| FR-07 | Offline: show last data with timestamp and "may be outdated" | MUST | Airplane-mode test |
| FR-08 | Optional daily notification if tomorrow is Poor or worse | SHOULD | Local only, user-controlled |
| FR-09 | Hindi + English | SHOULD | Strings reviewed by native speaker |
| FR-10 | Attribution screen: data sources, licences, disclaimers | MUST | Links work |
| FR-11 | Status indicator: forecast not updated in >X hours | MUST | Simulated failure test |

## 6. Non-functional
- No personal data collected by me; no accounts; no analytics SDK in MVP.
- Page/app load fast on a low-end phone and slow network; JSON files small.
- Reliability: if ingestion fails, show last good forecast with a clear stale warning; never show an empty "good air" by default.
- Reproducible: any reported metric can be regenerated by one command.

## 7. Success criteria
- [ ] Evaluation report on a frozen held-out winter + prospective results since launch of archiving.
- [ ] Decision rule (AQ_12) applied honestly and result shown to users.
- [ ] Web page live, with real users by early December.
- [ ] Demo video, README with measured numbers, APK on GitHub.
- [ ] Play: closed test completed, production applied (if gates pass).

## 8. Safety and honesty requirements
- Forecasts can be wrong. Say so in the app, near the forecast.
- Never display "Good" because data is missing. Missing = "No data".
- Health note is general information, not medical advice. Link to official CPCB information.
- Not an official service. No government logos.
